# 成片审查

以目标故事的 JSONL 记录、`series/xiangwei/assets/shot_library.json`、声音 manifest 和单集 `timing.json` 为依据。HyperFrames 工程须先按其技能要求运行完整 `check`；审查要覆盖当前导出的 MP4，不能只看 HTML 预览。

## 检查顺序

1. 从剧本和实际配音时长重建工程；重复运行重建脚本，确认镜头动作、字幕和音频轨不退回旧状态。修复 `check` 的错误并审阅警告。
2. 在开头、转折、电话或其他道具动作、笑点、学习卡两个阶段抽帧。逐句核对说话人、听者反应、人物位置、服装、道具手别和镜面逻辑。人物切换时避免交叉淡化造成重影。
3. 将英语原文、中文、音频 manifest、SRT 与 `timing.json` 对齐；用实际声音长度计算台词速度和停顿。确认核心句在故事中两次有用途，学习卡有跟读留白及一个可迁移变体。
4. 导出后用 `ffprobe` 核对分辨率、帧率、时长及音轨；从 MP4 再抽关键帧。若可直接听辨，检查发音、音色、断句和混音；否则明确标记“未听辨”，不作听感结论。

正例：同一只手持手机跨镜头一致；爸爸说“得快点”时指向椅子，顾客准备坐下；学习卡有原句和换词句各自的停顿。反例：只因 `check` 通过就宣称发音准确；重新构建后动作丢失；只检查工程而未检查导出 MP4。

## 输出与失败处理

出一份简短 QA 记录：版本、检查命令和结果、时间轴/字幕对齐、逐帧连续性、MP4 参数、听辨状态、待修项与结论。失败项写具体时间和镜头，修复源剧本或生成脚本后重建、复查；不要直接修饰导出 MP4 来掩盖源工程问题。
